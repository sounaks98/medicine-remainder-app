## 3. Operator inventory (P2-03)

Generated by `python tool/model_spike/inspect_onnx.py` → `tool/model_spike/inspect_report.json`.

### 3.1 `vision_encoder_q4f16.onnx`

- **Opsets:** ONNX 14, `com.microsoft` 1  
- **Nodes:** 873  
- **Notable ops:** `MatMulNBits` (73), `MatMul`, `Softmax`, `Conv`  
- **Inputs:** `pixel_values` `[batch, num_images, 3, 512, 512]` float32; `pixel_attention_mask` bool  
- **Outputs:** `image_features` `[*, 64, 960]` float32  

### 3.2 `embed_tokens_q4f16.onnx`

- **Nodes:** 2 (`Gather`, `Cast`)  
- **Inputs:** `input_ids` `[batch, sequence_length]` int64  
- **Outputs:** `inputs_embeds` `[batch, sequence_length, 960]` float32  

### 3.3 `decoder_model_merged_q4f16.onnx`

- **Opsets:** ONNX 14, `com.microsoft` 1  
- **Nodes:** 1,614  
- **Notable ops:** `MatMulNBits` (225), `MultiHeadAttention` (32), `RotaryEmbedding` (64), `SkipSimplifiedLayerNormalization` (64)  
- **Inputs:** `inputs_embeds`, `attention_mask`, `position_ids`, `past_key_values.{0..31}.{key|value}` (fp16 KV, 5 heads × 64 dim)  
- **Outputs:** `logits`, `present.{0..31}.{key|value}` (65 tensors total)  

**Q1 (unsupported ops on ORT Mobile):** `MatMulNBits` and fused attention ops load on **onnxruntime-android 1.20.0** (x86_64 emulator). Physical ARM64 still needs verification on a 4 GB phone.

## 4. Desktop reference inference (P2-04)

Script: `tool/model_spike/run_reference.py`  
Sample output: `tool/model_spike/output/reference_generation.json`

| Metric | Value |
|--------|-------|
| Prompt | “Describe this image in one sentence.” (synthetic 512×512 image) |
| Tokens generated | 13 (EOS) |
| Wall time | 63.3 s |
| Throughput | ~0.21 tokens/s |
| Mode | `full_sequence_prefill_per_token` (see below) |

### 4.1 KV-cache decode blocker (desktop)

The Hugging Face sample loop (KV cache, single-token decode steps) **fails on the q4f16 decoder** with ONNX Runtime 1.19+ on CPU after the first prefill step:

```text
Shape mismatch attempting to re-use buffer. {1,1,960} != {1,1137,960}
```

Prefill with empty `past_key_values` succeeds; the first decode step with non-empty KV fails. Workaround used for regression output: re-run **full-sequence prefill** each token (`enable_mem_pattern = false`, `inputs_embeds` as float32). This proves graph correctness but is **not viable on mobile** (latency).

## 8. Phase 2 decision (P2-07) — **NO-GO**

**Decision:** **Do not proceed to Phase 3 SmolVLM integration** for v1. Continue with **ML Kit OCR + rules + manual review** (`SmolVlmOnnxExtractionService` remains stubbed).

### Rationale (§5.4 go criteria)

1. **On-device autoregressive inference is unproven** — no ≥50-token run on Android; desktop q4f16 KV decode fails on standard ORT CPU loop.  
2. **Performance** — full-sequence fallback is ~0.2 tokens/s on desktop for a short prompt; extrapolation exceeds MVP latency budget on 4 GB hardware.  
3. **Risk** — heavy reliance on `MatMulNBits` / fused attention on mobile ORT; peak memory not validated under combined sessions + KV.  
4. **Product** — OCR-first MVP already meets offline extraction needs; VLM adds large download (~341 MB) and engineering cost without a verified inference path.

### Blockers to revisit later

- Fix or replace q4f16 decoder export / ORT version pairing for stable KV decode.  
- Profile peak PSS on a physical 4 GB ARM device with all sessions resident.  
- Re-run prescription JSON benchmark (5 de-identified images) if generation becomes stable.
